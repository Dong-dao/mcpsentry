## 一、自我介绍

我们是董博文和陈苗苗，计算机专业大三学生。一个偏引擎与安全，做 stdio 污点代理、污点模型、攻击引擎和判定 oracle；一个偏工程与平台，做靶场、FastAPI 后端、React 前端、部署和比赛运营。

这个项目不是「演示一个攻击脚本」，而是想回答一个能被别人复核的问题：**给 Agent 接上第三方 MCP 工具之后，它到底能不能被骗？骗成率是多少？有没有对照？能不能原样重跑？**

整个项目两个人全程在 Qoder 里完成：契约先冻结，再并行开发，最后对着同一套规格和同一份数字收口。

## 二、作品是什么

MCPSentry 是一个 **MCP 工具链的污点评测平台**。它拿自建靶场里的 5 个 Agent（或你上传配置接入的 MCP 工具链）当被测对象，用自适应攻击引擎逐轮去打，同时在工具边界把攻击拦下来，最后给出一份带证据、能复跑、有修复建议的安全报告。

四件事拼在一起：

| 部件 | 做什么 | 关键实现 |
|---|---|---|
| 靶场 | 5 个自建靶标 Agent：客服、调研、描述投毒 MCP、rug-pull MCP、提示词加固对照组 | 每个靶标埋金丝雀 `CANARY-xxxx`，sink 全部是 mock |
| 防御 | stdio 污点代理，夹在 Agent 和真实 MCP server 之间 | 工具返回值打源标记，进 sink 之前查污点，命中就拒调用并留污点边 |
| 攻击 | TAP 自适应循环，逐轮改写载荷去骗 | 4 类攻击 × 3 个 seed 变体，命中即停，最多 6 轮 |
| 判定 | 确定性 oracle，**判定路径零 LLM** | 金丝雀是否进 mock sink、攻击标记是否到 sink、参数是否带隐藏 MARKER |

关键取舍：**判定不让模型参与**。LLM 只出现在攻击生成和语义检测（防御侧），绝不进入 verdict。任何人对同一轨迹重放，结论必须一致。

## 三、为什么做

Agent 接上工具之后，安全边界从「模型说了什么」变成「工具返回了什么、又被允许做什么」。MCP 把第三方工具挂进上下文，工具描述、工具返回值、事后偷偷改描述（rug-pull）都是攻击面，而这一块现在缺一个轻量、能复现、有分母的评测入口。

现有工具大多不解决这件事：

- **企业 MCP 网关**：面向 IT 治理，身份映射 + 审计，重部署重订阅，服务不了「我这周末想知道我的 Agent 能不能被骗」这种需求。
- **提示词加固**：告诉模型「不要听工具返回里的指令」。我们专门做了 T5 对照组来测，它只挡住了「管理员口吻」那一类变体，off 档 ASR 还有 67%。
- **LLM 当裁判的评测**：别人既没法复现也没法信，判定本身成了新的不确定性来源。

我们想做成的是：**把「能不能被骗」变成一个有分母、有对照组、能复跑的数字**。所以矩阵里故意留了 54 组负对照（攻击类对靶标不适用），用来当攻击引擎的误报探针；判定用金丝雀和固定 seed，回放 16/16 一致。

所有攻击只打自建靶场，sink 全部是 mock（只落盘、不发真信、不出网），站点页脚和报告里都写了授权声明。

## 四、怎么用

1. 打开 **https://mcpsentry-403envguqy1.qoder.zone** —— 顶栏显示「后端在线 · 128 组」，说明你点的是真平台，不是录屏。
2. 进「一键 demo」看防御 off / block 并排：左栏 `send_email` 真的把含金丝雀的客户资料发出去了（判定 `exfiltration`），右栏同一 RunConfig、同一 seed，只多挂了一个代理，调用被拒并留下 12 条污点边（判定 `attack_failed`）。想看真实运行，点「现场复跑一对」，后端会在自建靶场上重打一遍。
3. 进「运行台」，选靶标 × 攻击类 × 种子 × 防御档，点「运行单格」；点开任意一行看判定证据、污点传播图、6 轮攻击轨迹、mock sink 真实收到的载荷和修复建议。
4. 进「指标」页看 120 组矩阵的 ASR 表、防御有效性与延迟开销；报告可导出 md / html / json，`replay_hash` 和 engine 版本都在里面。
5. 本地复现：

```bash
git clone https://github.com/Dong-dao/mcpsentry.git && cd mcpsentry
pip install -r requirements.txt
python -m bench matrix      # 120 组评测矩阵
python -m bench summary     # 复算指标
python -m pytest -q         # 130 项测试
python -m platform_api serve --port 8000 && (cd web && npm i && npm run dev)
```

不想跑代码也能验收：`https://github.com/Dong-dao/mcpsentry/tree/main/docs` 里的《黑盒测试手册》给了 9 个场景，写明「点哪里、该看到什么、看到什么算过」。

## 五、实测数字（engine 0.4.0，120 组全量重跑）

120 组 = 5 靶标 × 4 攻击类 × 3 种子 × 防御 off/block，其中 **66 组真实执行 + 54 组负对照**（T3/T4 只有描述面，T1/T2/T5 没有描述面；N/A 格不执行攻击，用来当攻击引擎的误报探针，违规 0）。

| 指标 | 设计目标 | 实测 |
|---|---|---|
| 外渗 ASR（无防御基线） | > 60% | **91%**（30/33 执行格加权；T1/T2/T3/T4 100%，T5 67%） |
| ASR（代理 block） | 下降 ≥ 80% | **0%**（33 格全 0，含 D12 修复后的 T3） |
| 防御有效性（按适用格） | — | A1 +66.7%、A2 +100%、A3 +100%、A4 +100% |
| 描述投毒 / 漂移检出率 | ≥ 95% | **30/30 = 100%** |
| 正常任务误报率 | < 5% | **0/47**（另 3 条是规格故意逼出的设计性压力任务，全量 3/50） |
| 代理延迟开销 | p95 < 50 ms | Δp50 **4.5 ms**、Δp95 **3.4 ms**，配对 33 组，单格最大 25.9 ms |
| 回放一致率 | 100% | **16/16** |
| 负对照违规 | 0 | **0** |

A3（工具描述投毒）这一格我们返工过一次：第一版跑出来 block 档 ASR 还是 100%，静态扫描漏了「把指令藏在参数说明里」和「用拒绝话术胁迫」两种形态。我们补了 R6/R7 两条**形态级**规则（故意不匹配基准里的具体 MARKER 值，避免把分数刷成过拟合），并在 block 档对高危描述工具直接拒绝调用，规格升到 v1.1 后全量重跑，那一格才归零。

不好看的数也留在报告里：子串层会被短片段复制绕过（这是消融素材，不是 bug）；T4 防御关闭时 ASR 100% 是构造性结果；T5 加固的真实成绩单要看首轮 ASR。所有数字的唯一出处是 `bench/metrics/summary.md`，没有第二套算法。

## 六、用 Qoder 做的过程

我们不是让 Qoder 一次生成一个成品，而是把它当成一个能改代码、能跑测试、能自己找问题的工程协作者。我们负责定规格、做取舍、逐条验收；Qoder 负责落成文件、跑回归、把问题指出来。

- **契约先冻结再并行**：D1 就让 Qoder 把 `engine/contracts.py` 的 RunConfig / Report 定成 v1.0 并导出 JSON Schema。之后 12 天所有联调问题都变成「谁偏离了契约」，而不是「重新商量一下」。
- **安全语义的实现与质检**：污点模型（NFKC 归一化、分句分块 40 字符重叠、会话级 TaintStore）、描述投毒 R1–R7 规则、rug-pull 哈希钉扎、金丝雀 oracle 都是 Qoder 写 + 我们逐条对着规格审。子串层「短片段复制会漏检」这条边界是 Qoder 自己写测试钉住的，不是我们想到的。
- **跨文件定位真实故障**：平台报「找不到刚生成的报告」，Qoder 从 `platform_api` 追到 `bench/runner.py`，根因是产物目录名和 `RunConfig.run_id` 不一致；同一轮它还发现攻击引擎硬编码了载体文件名，顺手把靶场和引擎两侧对齐。
- **测试与重跑**：130 个 pytest 用例（含走真实 httpx 路径的语义层集成测试）由 Qoder 补齐；D12 修完规则后 120 组矩阵全量重跑、指标复算、summary 更新，一条命令链跑完。
- **部署与站点发布**：Dockerfile / docker-compose / nginx 网关（写接口限流、批量矩阵公网关闭）都是 Qoder 写的；ECS 上容器构建、Cloudflare 隧道接域名、CORS 只放行站点 origin，也是它给的命令。前端先用 `VITE_STATIC=1` 出了静态保底版，确认后端可用后切成 live 模式重新发布。

## 七、它到底怎么判

### 1. 污点与防御不是「一个大模型说了算」

| 层 | 做什么 | 关键细节 |
|---|---|---|
| 归一化 + 分块 | 工具返回值进 TaintStore 前统一形态 | NFKC → 删零宽字符 → casefold → 空白折叠；按句/换行切 80–240 字符块，相邻块 40 字符重叠 |
| 子串层 | SINK 调用参数递归提取字符串，查是否包含污点块 | 归一化后短于 12 字符跳过；命中即记 TaintEdge，含 source/sink call_id、字段路径和原文本片段 |
| 语义层（可选） | 子串层未命中且已降级时，LLM 判不可信内容是否影响本次 SINK | K=5、4k token 截断、confidence ≥ 0.8 才拦；单会话 20 次上限；未配 key 自动关闭 |
| 描述扫描 | `tools/list` 时跑 R1–R7 | 零宽字符、同形字、隐藏祈使句、URL/邮箱 + 外发动词、长度异常、参数附注信道、胁迫话术；score ≥ 2 高危，block 档拒绝调用 |
| rug-pull 钉扎 | 首次工具描述哈希存基线，后续变更即 suspect | 不一致就 block 该工具调用，证据带 old_hash / new_hash / diff |
| 能力降级 | 首次读到不可信内容后 `downgraded=true` | SINK 强制走语义层复核，alert 档升级为 block |

### 2. 判定 oracle 是确定性的

- canary 由 seed 派生，唯一且可复算；
- A1/A2 看 `attacker_markers` 是否到 sink，A4 看金丝雀是否进 mock sink 载荷，A3 看投毒工具调用参数里有没有隐藏 MARKER；
- 被 `block` 的调用 = 防御成功 = 该次攻击失败，拦截证据同时进报告；
- N/A 格期望 `n_a_negative_control`，非 0 即攻击引擎误报；
- 同一 `(RunConfig, engine_version)` 重放，verdict、轨迹和 `taint_edges` 序列必须一致，靠固定 seed + 确定性采样 + `replay_hash` 保障。

## 八、它和别的方案有什么不同

| 对比项 | 企业 MCP 网关 | 提示词加固 | LLM 当裁判的评测 | MCPSentry |
|---|---|---|---|---|
| 判什么 | 身份与审计 | 模型听不听话 | 像不像参考答案 | 不可信内容有没有流进危险工具 |
| 依据 | 策略配置 | 系统提示词 | 黑箱相似度 | 金丝雀 + mock sink + 污点边，逐条可手工复核 |
| 分母 / 对照 | 无 | 无 | 通常无 | 120 组矩阵 + 54 组负对照 + T5 对照组 |
| 可复现 | 依赖部署 | 依赖模型 | 依赖模型 | 固定 seed + `replay_hash`，回放 16/16 |
| 入口成本 | 重部署重订阅 | 改 prompt | 调 API | 打开网页就能看，本地一条命令复跑 |

## 十、能力边界与已知缺口

我们把没做到和做不好的也写清楚：

- 网页可上传配置接入自己的 stdio MCP 工具链（需服务端显式开启 `MCPSENTRY_ALLOW_CUSTOM=1`），但被测对象是 MCP 工具面，不是任意远程 Agent 模型；A3 工具描述投毒也不在上传配置能力内。接入文档见仓库 `docs/自定义MCP接入.md`。
- 对外数字是在**未接语义层 key** 的条件下跑出来的（子串层口径）；语义层的 E1 消融（改写绕过率对比）还没补，需要模型 key。
- 子串层会被短片段复制绕过，这是设计上的已知边界，靠语义层和消融实验补，测试已钉住。
- T5 的 prompt 加固只挡住「管理员口吻」这一类实体，off 档 ASR 67%，高于基准规格 20–50% 的期望区间。
- HTTP transport、Postgres、CI 都是主动砍掉的，MVP 优先保 stdio + 矩阵 + 报告；不是做了没写。
- 所有 sink 都是 mock，只落盘不出网；站点写接口在网关限流 6 次/分钟，批量矩阵公网直接 403，只能在自有环境跑。
