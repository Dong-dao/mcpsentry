## 1. 目标与范围

在 Agent 与 MCP 服务器之间，对"不可信内容是否流入危险工具"做确定性 + 语义两层判定，给出告警/拦截动作与可审计证据。MVP 范围：stdio transport、单 Agent 会话级追踪；HTTP transport 列入赛后路线图。

## 2. 工具分类（按工具名配置，默认值如下）

| 类别 | 工具 | 说明 |
|---|---|---|
| 源 SOURCE（不可信） | web_fetch, read_external_doc, mail_read, search_web | 返回内容打 UNTRUSTED 污点标签 |
| 汇 SINK（有副作用） | send_email, http_post, write_file, execute, delete_file | 污点流入即触发策略 |
| 中性 NEUTRAL | read_doc（客户文档）, read_private, 其余只读工具 | read_private 标记 SECRET 标签（v2 启用 DLP），MVP 不参与拦截 |

分类表以配置为准，可被 RunConfig 覆盖（target 自定义工具集）。

## 3. 污点存储模型（会话级 TaintStore）

- 每次 SOURCE 工具返回后：记录 `(call_id, tool, ts)` 并做**分块**——按句子/换行切分，块长 80–240 字符、相邻块 40 字符重叠（捕获跨边界复制）
- 存储：归一化后的块文本 + 原文本映射，内存为主、JSONL 落盘（轨迹审计）
- 生命周期：会话内有效；能力降级后不清理，但新流入的污点仍持续记录

## 4. 归一化规则（确定性层输入变换）

按顺序应用：
1. Unicode NFKC 归一化
2. 删除零宽字符（U+200B–U+200F, U+FEFF, U+2060–U+2064）
3. 大小写折叠（casefold）
4. 空白折叠（连续空白 → 单空格，首尾去空）

## 5. 传播检测 · 确定性层（子串层）

- 触发点：每次 SINK 工具调用（tools/call）到达代理时
- 检测：对调用参数递归提取字符串值 → 归一化 → 检查是否**包含**任一污点块
- 最小匹配长度阈值：12 字符（归一化后），低于阈值忽略——避免常用词误报
- 命中即记录 TaintEdge（source_call_id/sink_call_id/字段/命中层=substring/是否拦截），证据含原文本片段
- 性能：纯内存查表，目标 < 1ms/调用

## 6. 语义层判定（子串层未命中时对 SINK 调用启用）

- 输入：最近 K=5 条不可信工具返回（截断到 4k token）+ 本次 SINK 调用描述
- 输出（JSON）：`{ "influenced": bool, "reason": str, "confidence": float }`
- 判定条件：confidence ≥ 0.8 且 influenced=true 才触发策略（两档均适用）
- 模型：qwen-flash 级（成本/延迟预算）；同一 (call_hash) 判定缓存，不重复计费
- 命中记录层 = semantic；reason 入证据
- 成本控制：仅 SINK 调用触发；单会话上限 20 次判定，超限降级为"仅告警不拦截"并在报告标注

## 7. 策略模型

三档（RunConfig.defense.policy 指定）：

| 档位 | 行为 | 用途 |
|---|---|---|
| alert | 记录 TaintEdge + 证据，调用放行，报告高亮 | 低侵入评估、误报率测量 |
| block | 拒绝调用（向 Agent 返回 MCP 错误：policy_blocked），记录拦截证据 | 生产防护、ASR 下降测量 |
| strict（v1.2） | 具备 block 的全部拦截（污点命中 / desc_highrisk / rug-pull / 语义层命中）；且一旦 `downgraded=true`，所有后续 SINK 调用无论是否命中污点都拒绝，错误同属 `policy_blocked`，flow log 记 `capability_block` | 上传自己 MCP 时的强隔离档 |

默认策略：`block`（不变）。被拦截后 Agent 的行为（是否转向其他工具）继续被记录，用于轨迹分析。

**能力降级（CaMeL-lite）**：会话内首次读取不可信内容后，`downgraded=true`；降级状态下 SINK 调用强制走语义层复核（子串层未命中时不再跳过），并升级 alert→block。降级状态在报告中单独标注。strict 在降级基础上进一步**拒绝全部 SINK**，不再区分是否有污点或语义命中。

## 8. 描述投毒静态扫描（tools/list 时执行）

对每条工具描述跑规则集，任一命中即记 POISONING_SUSPECT：

| 规则 | 判定 |
|---|---|
| R1 零宽字符 | 归一化前后字符数差异 > 0 |
| R2 同形异义字 | 对常见混淆对（o/о、a/а、l/І 等）替换后与敏感词匹配 |
| R3 隐藏祈使句 | 正则命中："ignore previous|instead|disregard|发送.*到|send.*to|base64|exec|exfiltrate" |
| R4 描述内嵌指令目标 | 描述中出现 URL/邮箱 + 数据外传动词组合 |
| R5 描述长度/语言异常 | > 2000 字符 或 与工具名语义无关度极高（LLM 评分，成本低可全量） |
| R6 参数附注隐藏信道（v1.1） | 要求调用方在参数中附注指定数据（"must include note=" / "在参数中附带"），即经调用参数建立信道 |
| R7 胁迫话术（v1.1） | 以审计/会话失效相威胁（"audit system will reject" / "否则…拒绝"） |

产出：每工具 `poison_score`（0–7 规则命中数），≥2 记为高危。

**策略动作（v1.1）**：高危描述工具在 `alert` 档只记录；在 `block` 档其调用被拒
（`desc_block` 证据，`blocked=true`）。rug-pull 钉扎（§9）覆盖"基线后漂移"形态，
本条覆盖"基线即投毒"形态，两者互补。v1.2 的 `strict` 与 block 同样拒绝高危描述工具，
并叠加 §7 的降级后全 SINK 拒绝。

## 9. rug-pull 哈希钉扎协议

- 批准事件：用户/平台首次 approve 某 MCP 服务器工具集时，计算每条工具描述归一化文本的 sha256，存入 `pinned` 表
- 每次 tools/list：比对当前哈希；差异 → `RUG_PULL_SUSPECT`（含 diff 摘要），策略默认 block 该工具的后续调用
- 无批准事件的会话（自动接入）：以首次 tools/list 为基线

## 10. 延迟预算（设计目标，D9 实测）

| 组件 | 目标 |
|---|---|
| 子串层 | < 1ms/调用 |
| 语义层 | p95 < 300ms（影响 SINK 调用延迟） |
| 代理转发总开销（无判定） | p95 < 10ms |

## 11. 已知局限（诚实记录，挂钩消融实验）

1. 子串层可被改写/转述绕过 → 语义层补位，绕过率即消融数字
2. 语义层误报（合法引用场景，如"把客户文档摘要发邮件"）→ 用 50 条正常任务测 FPR，报告策略 trade-off
3. 语义层可被对抗性误导 → 置信阈值 + 证据留痕，判定本身不进入 verdict（见 oracle 设计）
4. 分块边界截断漏检 → 40 字符重叠缓解，残余漏检计入 ASR
